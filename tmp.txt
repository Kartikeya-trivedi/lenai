### Step 1: Set Up Supabase (Database & Storage)
1. Go to [Supabase](https://supabase.com/) and create a new project.
2. **Get the Database Pooler URL (CRITICAL for IPv4):**
   - In your Supabase Dashboard, go to **Project Settings** (the gear icon) → **Database**.
   - Scroll down to the **Connection string** section.
   - Click the **URI** tab.
   - Check the box that says **"Use connection pooling"**.
   - Copy the connection string. It will look something like this: `postgresql://postgres.yourproject:password@aws-0-region.pooler.supabase.com:6543/postgres`
   - *Note: You must change `postgresql://` to `postgresql+asyncpg://` when we use it in Step 4.*
3. **Get your S3 Storage Keys:**
   - In your Supabase Dashboard, go to **Project Settings** → **Storage**.
   - Under **S3 Access Keys**, click **New Access Key**.
   - Copy your **Access Key ID** and **Secret Access Key**. 
   - Note your Project ID (the random letters in your Supabase URL, e.g., `aygarantocxypzrhnwhh`).

### Step 2: Set up Redis & Qdrant Cloud
1. **Redis:** Go to [Upstash](https://upstash.com/) or Redis Enterprise Cloud. Create a free Redis database. Copy the connection string (it will look like `rediss://default:password@something.upstash.io:6379`).
2. **Qdrant:** Go to [Qdrant Cloud](https://cloud.qdrant.io/). Create a free cluster. Copy your **Cluster URL** (e.g., `https://xxx.aws.cloud.qdrant.io:6333`).

---

### Step 3: Bootstrap the Supabase Database
Your new Supabase database is completely empty. We need to create the tables and generate your Admin API key using your local Docker stack.

1. Open the `.env` file on your local machine (`C:\Projects\len_ai\.env`).
2. Find the `DATABASE_URL=` line.
3. Replace it with your Supabase Pooler URL from Step 1, ensuring it starts with the async driver:
   ```env
   DATABASE_URL=postgresql+asyncpg://postgres.yourproject:yourpassword@aws-0-region.pooler.supabase.com:6543/postgres
   ```
4. Open PowerShell and run this command to start the API (which will automatically build all the tables in Supabase):
   ```powershell
   docker compose up -d api
   ```
5. Wait 10 seconds, then run this command to generate your very first API Key:
   ```powershell
   docker compose exec api python -m scripts.seed_db
   ```
6. **SAVE THE API KEY IT PRINTS OUT!** You will need this to log into the Playground later.

---


However, it failed on the very last step: **uploading the generated image to storage**.

**Why it failed:**
The Modal cloud container is trying to upload the final image to `http://minio:9000`. Since MinIO is running locally on your laptop in Docker, the Modal cloud container cannot reach it. Because your backend is in the cloud, your storage needs to be in the cloud too!

**The Fix:**
Since you are already using Supabase for your database, you can use **Supabase Storage** (which has a built-in S3-compatible API) for free! 

Here is exactly how to fix it in 2 minutes:

### 1. Get your Supabase S3 Credentials
1. Go to your Supabase Dashboard -> **Project Settings** (gear icon).
2. Click on **Storage** in the left sidebar.
3. Scroll down to the **S3 Access Keys** section.
4. Click **New Access Key** and copy the `Access Key ID` and `Secret Access Key`.
5. Under "S3 Connection Info", copy your **Endpoint URL** (it looks like `https://<project-ref>.supabase.co/storage/v1/s3`).

### 2. Create the Storage Buckets
1. In the Supabase Dashboard, go to **Storage** (folder icon on the far left).
2. Click **New Bucket** and create a bucket named `inputs` (Make it **Public**).
3. Click **New Bucket** again and create a bucket named `outputs` (Make it **Public**).

### 3. Update your Modal Secret
Run this command in your terminal, replacing the placeholders with the values you just copied:

```bash
modal secret create lenai-storage-secret \
  MINIO_ENDPOINT="YOUR_SUPABASE_ENDPOINT_URL" \
  MINIO_ROOT_USER="YOUR_ACCESS_KEY_ID" \
  MINIO_ROOT_PASSWORD="YOUR_SECRET_ACCESS_KEY" \
  MINIO_USE_SSL="true" \
  MINIO_PUBLIC_ENDPOINT="YOUR_PROJECT_REF.supabase.co/storage/v1/object/public"
```

Once you run that command, **just try generating the image again!** It will automatically use the new cloud storage buckets and the image will finally appear in your UI! Let me know when you've done this or if you run into any issues.
